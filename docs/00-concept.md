# Notes Agent

Notes Agent — личный помощник для ведения Markdown-заметок. С ним можно говорить обычным языком. Например, попросить найти старое решение по проекту или добавить новую договорённость в подходящую заметку. Агент сам выбирает нужные действия и уточняет запрос, если нашёл несколько равнозначных заметок.

## Устройство

- Приложение на Node.js и TypeScript живёт в отдельном репозитории. Заметки остаются в отдельном Git-репозитории и доступны через локальный клон. Правила оформления и структура заметок берутся из его `AGENTS.md`.
- Модель подключается через Sign in with ChatGPT. Первый шаг — проверить вход, получить список доступных моделей и выполнить один тестовый запрос по подписке. [План проверки](01-chatgpt-plan-access.md)
- Агентский цикл берём из готовой библиотеки. Модель выбирает инструмент по контексту, получает его результат и решает, продолжать или ответить. Конкретную библиотеку выберем после проверки доступа к моделям.
- Первая версия работает в терминале. Позже тот же агент можно подключить к веб-чату.

## Инструменты агента

- `search_notes` — находит подходящие фрагменты и возвращает пути к заметкам.
- `read_note` — читает актуальную версию заметки.
- `create_note` — создаёт Markdown-файл в существующей структуре.
- `update_note` — точечно обновляет заметку. Перед записью проверяет, что файл с момента чтения не изменился.

Доступ ограничивает код инструментов. Он проверяет, что путь указывает внутрь разрешённой области репозитория. Модель получает только операции над заметками. При конфликте версий агент перечитывает файл и решает, применима ли правка к новой версии.

## Как агент находит нужную заметку

Гибридный поиск объединяет поиск по словам и поиск по смыслу. Первый учитывает заголовки, пути и текст, второй сравнивает эмбеддинги запроса и разделов Markdown. Агент получает несколько лучших фрагментов с путями, открывает подходящую заметку и работает с её актуальным содержимым.

Для прототипа можно держать текстовый индекс в SQLite FTS5 и сравнивать векторы в памяти. Индекс строится из Markdown и обновляется для изменённых файлов. Способ получения эмбеддингов выбирается отдельно от доступа к моделям по подписке. Для личных заметок локальная модель эмбеддингов позволяет строить индекс без отправки всего корпуса внешнему сервису.

## Первые проверки

1. Подтвердить доступ к модели по подписке.
2. Проверить, что агент находит нужную заметку по формулировке, в которой нет её точного названия.
3. Проверить, что он дополняет правильный раздел и сохраняет остальные части файла. При неоднозначности агент уточняет, куда писать.
